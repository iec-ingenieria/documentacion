    2. 4️⃣ edbtoinf

    Uso de la interfaz

    La interfaz de edbtoinf es un asistente (wizard) que carga el modelo ETABS, propone solo los parámetros NCh433 y el perfil bio-sísmico, deja editar los niveles para el cálculo de drift y genera el Informe Ejecutivo. El flujo es:

    Cargar EDB  ->  autopropuestas  ->  Paso 1 Parámetros  ->  Paso 2 Niveles
            ->  (Paso 3 Opcionales, solo suelo F)  ->  Generar Informe

    Cargar el modelo

    La barra superior tiene el botón Cargar EDB.... Al elegir el .edb, edbtoinf se conecta a ETABS y rescata los datos (modal de progreso "Cargando datos desde ETABS..."). Terminado el rescate, habilita los controles y rellena las propuestas automáticas.

    Qué propone cada control al cargar

    Control Cómo se propone
    Categoría / Zona / Suelo Del nombre del espectro sísmico del modelo, según la convención IEC C<cat>Z<zona>S<suelo> (p. ej. CIIZ2SC → Categoría II, Zona 2, Suelo C).
    H₀ [m] De la cota de los pisos P*: cielo del último piso menos cielo del último subterráneo. Excluye base, subterráneos S* y salas de máquina SM*.
    Líneas X / Y Por la heurística de líneas resistentes (ver más abajo).
    Niveles para drift Carga el .drift previo si existe junto al .edb; si no, genera una propuesta automática.

    Todas son propuestas: el usuario las revisa y corrige antes de generar.

    Paso 1 — Parámetros

    Reúne la identificación NCh433 y el perfil bio-sísmico.

    Identificación NCh433:

    • Categoría, Zona, Suelo (propuestos del espectro).
    • Sistema: pórtico o muro. Filtra las opciones del combo Material.
    • Material: el sistema/material de la Tabla 5.1 de la NCh433 (por ejemplo HA, OMF, SMF). De aquí salen R y R0 tabulados.
    • TFR: tolerancia para el factor de reducción.

    Perfil bio-sísmico:

    • H₀ [m]: altura del edificio para el perfil.
    • Líneas X / Líneas Y: número de líneas resistentes por dirección.
    • Modo pred. X / Modo pred. Y: modo predominante por dirección (0 = automático, se elige por masa modal participante).

    Paso 2 — Niveles para drift

    Un cuadro de texto editable con el mapeo NIVEL SUP → NIVEL INF: contra qué nivel inferior se mide la deriva de cada nivel superior. Botones:

    • Generar propuesta: cada nivel contra el siguiente, el último contra base (empotramiento).
    • Cargar .drift / Guardar .drift: leer o persistir el mapeo.

    Use base como nivel inferior para empotrar contra la fundación. El formato y las reglas de columnas se detallan en Formato .drift.

    Sus ediciones no se pierden

    Si editó el mapeo a mano, Generar propuesta y Cargar .drift piden confirmación antes de reemplazarlo. Al generar el informe se usa lo que esté en el cuadro en ese momento, aunque no haya presionado Guardar .drift. Si el mapeo referencia un nivel inexistente, se muestra el error en vez de generar en silencio con un mapeo incorrecto.

    Paso 3 — Parámetros opcionales (suelo F)

    Esta pestaña solo se habilita con Suelo F. Para suelos A–E el espectro es el de la norma y no hay nada que completar aquí. Con suelo F el espectro lo define el estudio de sitio, así que se piden:

    • Parámetros sísmicos DS61: S*, T0*, T', n, p, A0.
    • Filas para examinar los archivos de espectro de sitio Sa(T) (aceleraciones, obligatorio) y Sde(T) (desplazamientos, opcional).

    Generar el informe

    La barra inferior muestra bullets de estado (EDB cargado, Niveles definidos). El botón Generar Informe Ejecutivo se habilita solo cuando ambos están en orden.

    Antes de generar

    edbtoinf hace un pre-flight: avisa si el PDF de salida está bloqueado por un visor abierto, para no perder el cálculo. Cierre el PDF anterior si lo tiene abierto.

    Al terminar aparece un modal "Informe listo" con Abrir PDF, Copiar ruta y Cerrar. La pestaña Log muestra el detalle del proceso con tags coloreados (info, advertencia, error, propuesta, detalle), incluido el diagnóstico de las propuestas automáticas.

    El HTML de derivas no se genera desde la interfaz

    La interfaz produce el PDF. El reporte HTML interactivo de derivas se genera solo desde los CLIs (edbtoinf-cli --drift-html o derivas-cli); ver Interfaz de línea de comandos.

    Persistencia por proyecto

    • Los parámetros del último informe se guardan por proyecto en un archivo oculto .<codigo>_params.json junto al .edb y se recargan al volver a ese modelo.
    • La última carpeta usada (separada para .edb y para espectros) se recuerda en ~/.edbtoinf_state.json.

    Propuesta de líneas resistentes

    El número de líneas resistentes X/Y que propone el Paso 1 sale de una heurística sobre el modelo, no de un valor fijo. A grandes rasgos:

    1. Suma el aporte horizontal por eje combinando tres familias de elementos: los piers (clasificados por orientación según su bounding box), las columnas (su corte local V2/V3 proyectado al global con el ángulo del eje) y los braces (componente horizontal del axial por sus cosenos directores 3D). Usa los casos sísmicos del modelo (Ex/Ey, con fallback a SX/SY y ExE/EyE).
    2. Agrupa por eje los elementos con coordenada cercana (tolerancia ~1 m) y calcula la fracción del corte que toma cada eje.
    3. Cuenta como línea resistente cada eje que toma ≥ 5% del corte capturado en ese piso.
    4. Toma la mediana de ese conteo sobre los pisos de torre (P##) con captura razonable, y descarta los pisos donde la captura no cierra.

    El log reporta los ejes detectados con el nombre de su grilla en el modelo, su fracción de corte y los pisos descartados, para que el ingeniero valide la propuesta antes de aceptarla.

    Es una propuesta, no una verdad

    Es una estimación geométrica/de esfuerzos. Para muros oblicuos, plantas muy irregulares o sistemas mixtos puede quedar corta o sobrar; revise el conteo contra el criterio del proyecto y corríjalo a mano si hace falta.
