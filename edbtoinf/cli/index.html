    EDBTOINF — modo headless (CLI)

    edbtoinf ofrece dos CLIs sin interfaz gráfica, pensados para scripts, CI y agentes:

    • edbtoinf-cli: genera el Informe Ejecutivo IE_<codigo>.pdf (y, opcionalmente, el HTML de derivas).
    • derivas-cli: genera solo el reporte HTML de derivas <codigo>_derivas.html, sin el PDF ni el perfil bio-sísmico.

    Los dos comparten el mismo modelo de inputs: cambia solo la salida. Ambos heredan los flags comunes y los exit codes del marco de los CLIs (--json, --quiet, --verbose, --schema; exit codes 0–5).

    Lo único obligatorio además del modelo es el sistema y el material

    --edb, --sistema y --material son requeridos. Todo lo que la interfaz propone sola (--categoria, --zona, --suelo, --h0, --lineas-x, --lineas-y, el .drift) se infiere del modelo si se omite, igual que en la interfaz.

    edbtoinf-cli

    Genera IE_<codigo>.pdf en la carpeta del .edb (o en --out-dir).

    edbtoinf-cli --edb R4501.edb --sistema muro --material HA

    Entrada y sistema sismorresistente

    Opción Descripción Default
    --edb PATH Modelo ETABS de entrada. Requerido. —
    --sistema {portico,muro} Sistema sismorresistente. Requerido. —
    --material STR Material/sistema NCh433 Tabla 5.1 (p. ej. HA, OMF, SMF). Requerido. Se valida contra el sistema. —
    --tolerancia FLOAT Tolerancia del factor de reducción (TFR). Debe ser > 0. 0.005

    Identificación NCh433 (se infiere del espectro IEC si se omite)

    Opción Descripción Default
    --categoria {I,II,III,IV} Categoría de ocupación. auto
    --zona {1,2,3} Zona sísmica. auto
    --suelo {A,B,C,D,E,F} Tipo de suelo. auto

    Sin estos flags, edbtoinf-cli parsea el nombre del espectro del modelo (convención IEC C<cat>Z<zona>S<suelo>). Si el nombre no cumple la convención, falla pidiendo el flag a mano.

    Perfil bio-sísmico

    Opción Descripción Default
    --h0 VALOR Altura H₀ [m]: un número > 0 o auto (cota de pisos P*). auto
    --lineas-x VALOR N° de líneas resistentes X: un entero ≥ 0 o auto (heurística). auto
    --lineas-y VALOR N° de líneas resistentes Y: un entero ≥ 0 o auto. auto
    --modo-x INT Modo predominante X (0 = automático por masa modal). 0
    --modo-y INT Modo predominante Y (0 = automático). 0

    Niveles para drift

    Opción Descripción Default
    --drift PATH .drift con el mapeo de niveles. Si se omite se autogenera (cada nivel vs. el siguiente, último vs. base). auto
    --drift-out PATH Escribe el .drift efectivamente usado a este archivo. —

    Ver Formato .drift.

    Override de R / R0

    Opción Descripción
    --override-r FLOAT Sobreescribe el R tabulado (sistemas no tipificados en Tabla 5.1). Se valida contra el conjunto discreto de corte máximo.
    --override-r0 FLOAT Sobreescribe el R0 tabulado. Debe ser > 0.

    Suelo F (overrides + espectro de sitio)

    Obligatorios solo si el suelo es F (explícito o inferido):

    Opción Descripción
    --override-s FLOAT Parámetro S del suelo. Obligatorio si suelo = F.
    --override-t0 FLOAT Parámetro T0 [s]. Obligatorio si suelo = F.
    --espectro-sa PATH Espectro de sitio Sa(T) tabulado (TXT/CSV; ya incluye I·S·A0). Obligatorio si suelo = F.
    --override-tprima FLOAT Parámetro T' [s]. Opcional.
    --override-n FLOAT Parámetro n. Opcional.
    --override-p FLOAT Exponente p de α(T). Opcional.
    --override-a0 FLOAT Aceleración efectiva A0 (fracción de g). Opcional.
    --espectro-sde PATH Espectro de sitio Sde(T) tabulado. Opcional; sin él, el subplot de desplazamientos sale "No disponible".

    Salida y reporte de derivas

    Opción Descripción Default
    --out-dir PATH Carpeta de salida. la del .edb
    --drift-html Genera además el HTML interactivo de derivas (<codigo>_derivas.html). off
    --metodo {iec,alternativo} Método del drift adicional en el HTML. iec

    Ver Reporte HTML de derivas y Control de desplazamientos para la diferencia entre los métodos.

    Ejemplos

    # Todo auto: cat/zona/suelo/h0/líneas/drift inferidos del modelo
edbtoinf-cli --edb R4501.edb --sistema muro --material HA

# Resultado estructurado para un agente
edbtoinf-cli --edb R4501.edb --sistema muro --material HA --json

# Fijando los parámetros NCh433 y H0 a mano
edbtoinf-cli --edb R4501.edb --sistema muro --material HA \
  --categoria II --zona 2 --suelo C --h0 24.5

# Pórtico, materializando el .drift usado y líneas en auto
edbtoinf-cli --edb R4501.edb --sistema portico --material SMF \
  --drift-out R4501.drift --lineas-x auto --lineas-y auto

# PDF + HTML de derivas en un solo paso
edbtoinf-cli --edb R4501.edb --sistema muro --material HA --drift-html

# Suelo F con espectro de sitio
edbtoinf-cli --edb m.edb --sistema muro --material HA --suelo F \
  --override-s 1.20 --override-t0 0.30 --espectro-sa sa.txt

    derivas-cli

    Genera solo <codigo>_derivas.html. Acepta exactamente los mismos flags de entrada que edbtoinf-cli (todos los grupos de arriba, incluidos --metodo, suelo F, --out-dir, --drift/--drift-out), salvo --drift-html (que no tiene sentido: la única salida ya es el HTML).

    Reusa el mismo preparar_datos + calcular_datos que el informe, incluida la corrección por corte máximo (5.9.2), así que el HTML cuadra exacto con el PDF.

    # Reporte de derivas, método IEC (default)
derivas-cli --edb R4501.edb --sistema muro --material HA

# Método alternativo
derivas-cli --edb R4501.edb --sistema portico --material SMF --metodo alternativo

    Salida

    En modo normal, ambos CLIs imprimen la ruta del archivo generado a stdout (Informe generado: ... / Reporte de derivas generado: ...) y el diagnóstico a stderr. Con --json emiten un objeto con outputs y un summary:

    {
  "app": "edbtoinf",
  "ok": true,
  "outputs": ["C:/proyectos/IE_R4501.pdf"],
  "summary": {
    "codigo": "R4501",
    "categoria": "II",
    "zona": "2",
    "suelo": "C",
    "h0": 24.5,
    "lineas_x": 6,
    "lineas_y": 5
  }
}

    derivas-cli agrega metodo al summary. Si se pidió --drift-out o --drift-html, esos archivos también aparecen en outputs.

    Validación previa (fail-fast)

    Antes de abrir ETABS, los CLIs validan: que existan el .edb, el .drift y los espectros indicados; que el material sea válido para el sistema; que los overrides de suelo F estén completos si el suelo es F explícito; y los rangos de --tolerancia y --override-r. Cualquiera de estos falla con exit code 3 (InputError) sin tocar el modelo.
